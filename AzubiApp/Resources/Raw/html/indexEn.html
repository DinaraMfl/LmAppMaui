ContaineroptimierungEnglish

A container optimization determines a cost-effective container combination for a calculated (trigger) quantity and, if necessary, the rounding up of this container optimization. In order for container optimization to be used, the quality criterion in the Compound group must be set to “Container optimization”.

Setting in the parameters

These are also created in the conditions > Conditions -> Units -> Conditions Quantities/ Prices/ Costs.

Setting in the conditions

If LCL containers are also to be taken into account, an additional line must be added under “Quantities, prices, costs”:

LCL stands for “Less than Container Load” and refers to a shipping method in which several shippers (suppliers) share one container.

Here, “gross vol.” must be selected as the reference. In addition, as above, the mix flag must be set and either “Additional supplier costs” or “Additional own costs” selected.

After filling, the total order is divided between the individual containers according to the previously determined optimum container combination. This is done as follows:

  • If an LCL container is included in the container combination, the order items are sorted by descending density and loaded into the LCL container one after the other until the intended volume is reached.
  • The order items and containers are sorted according to a suitable criterion, for example by density or possible residual density.
  • The order items are then distributed to the containers either by optimization unit or - if possible - by bin location.
  • After each assignment, the remaining density of the container is calculated and the order of the containers is adjusted accordingly.
  • If an item no longer fits into a container, the container with the smallest overrun of the permitted volume is selected. If a storage space restriction must be observed, exceeding the weight limit is considered less critical than exceeding the storage space capacity.
